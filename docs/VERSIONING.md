# 版本控管

## 版本與來源

- 根目錄 `VERSION` 是目前免手把版版本號的唯一來源；採 `主版.次版.修訂-alpha.序號`，目前 `0.1.0-alpha.8`。
- 測試期間每次交付有程式變更的新版，就增加 alpha 序號並更新 [CHANGELOG.md](../CHANGELOG.md)。已標記版本不重用於另一份程式碼。
- `v<版本號>` 為附註 Git 標籤，固定經測試的原始碼提交。禁止強制移動、刪除後重建或強制覆寫遠端標籤。
- 編譯檔的 ProductVersion 包含版本與 Git 短碼；未提交的工作區另有 `.dirty`。視窗顯示產品版本，狀態與啟動紀錄保存完整來源提交及 dirty 狀態。
- `alpha.5` 是事後命名的成功基準：原執行檔沒有內嵌版本，不能事後改寫它並宣稱原檔已有版本。保存原檔及校驗資料即可。
- 交付後的驗收文件、建置清單與研究工具可另作提交；不因此移動版本標籤或覆寫原執行檔。重新交付有應用程式碼變更的版本，必須增加版本號。

## 建置、驗證與交付

1. 更新 `VERSION` 與變更紀錄，完成程式碼審查及離線測試。
2. 提交程式碼，確認工作區乾淨，再執行：

   ```powershell
   .\research\controller-free-preview\Build.ps1 -RunTests -RequireClean
   ```

3. 建置自動使用全新的版本目錄，寫入 `BUILD.json` 與 `SHA256SUMS.txt`；不覆寫目前版本，不啟動 GUI、後端或 USB 裝置。既有 `v<版本號>` 若指向不同提交，建置拒絕以該號碼產出候選。
4. 使用下列唯讀工具驗證程式版本與檔案雜湊：

   ```powershell
   .\packaging\Verify-ControllerFreeBuild.ps1 -BuildDirectory <建置目錄> -RequireClean
   ```

5. 測試通過後，以附註標籤固定該提交並同步開發分支及指定標籤。標籤不等於 GitHub Release；正式下載、收費與第三方散布另有驗收條件。

每份 `BUILD.json` 保存來源清單、各檔 SHA-256、版本、Git 提交、建置時間、執行入口、依賴與離線測試狀態。檔案雜湊用來辨識與檢查完整性，不代表發行者數位簽章。測試成功也不等於 Sony 接受輸入；實機結果另記日期、模式、版本與使用者回報。

## 更新與回退

- 新版本先放獨立資料夾，保留上一個實際驗收可用版本與其校驗資料。
- 切換只處理「上班不要玩」及它自己建立的模擬裝置；不任意關閉或重啟 Remote Play，也不碰其他程式的裝置。
- 兩版本不能同時接管 F8 或同一組服務連接埠。由使用者安排可切換的時段，舊版正常退出後才開新版。
- 回退前先正常退出新版，再開已保存的舊版。按鍵設定與程式分離，位於 `%LOCALAPPDATA%\PSKeyboard\bindings.json`；格式變更前另存備份，不用舊程式強行覆寫新格式。
- `alpha.5` 至 `alpha.8` 均使用設定格式 2；alpha.7 只改新建／恢復時的預設，alpha.8 調整品牌外觀，皆不覆寫既有鍵位或連點。這不代表將來所有版本都能互相讀取設定。

目前主線使用免手把建置腳本。`packaging/Build-Preview.ps1` 保留為歷史實體中繼 alpha.4 封裝工具，不用它建立目前免手把版。
