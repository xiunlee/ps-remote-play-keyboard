# 連點、錄製與手把相容性驗證

更新：2026-10-29。產品名稱「上班不要玩」。當日免手把候選取得首次單機操作成功回報，測試保留既有官方 Remote Play 程序與連線。依使用者最新決定，**免手把成為主要產品方向**，接續優先驗證重開機、重連、長時間操作與乾淨安裝。其他實體手把相容性暫緩，既有 DS4 中繼保留為歷史備援；錄製腳本仍屬後續功能設計。

## 連點的最後確認規格

每個手把動作可各自選擇：

| 模式 | 操作 |
| --- | --- |
| 關閉 | 一般映射，按住就是長按，放開就釋放 |
| 按住連點 | 按住按鍵時重複按下／放開，實際放開鍵盤立即停止 |
| 按一下切換 | 第一次按下啟動，放開後繼續；第二次獨立按下停止 |

每個動作的週期間隔為 **20–5000 毫秒**，預設 **100 毫秒**。這是一次按下開始到下一次按下開始的時間；每週期約前半按下、後半放開。100 毫秒相當於排程每秒 10 次，但 USB 回報、串流及遊戲的取樣速度會影響實際辨識結果，不能保證遊戲一定收到每次極短脈衝。

用途包含讓 Remote Play 留在前景的掛網操作。依使用者最後確認，**切換到任何其他視窗會清除全部連點狀態；回到 Remote Play 不會自動恢復，要重新按鍵。** F8 暫停、修改設定、控制通道中斷、關閉程式及 Ctrl／Alt／Windows 快捷鍵也會清除連點。F8 是保留的全域暫停鍵。

鍵盤遊戲輸入僅在已核對安裝路徑的 Sony 官方 Remote Play 處於前景時接受；「上班不要玩」的設定視窗也不會觸發遊戲按鍵。其他視窗新按下的鍵不會被遊戲映射攔截；先前已攔截的按下仍會配對處理放開事件，避免留下不完整的按鍵狀態。此功能不向其他視窗注入鍵盤或滑鼠事件。

免手把主線直接產生虛擬手把輸出，不需要合併實體手把資料。歷史備援的實體中繼則只合併鍵盤產生的動作，不抹除實體手把操作；實體手把本身一直按著同一個按鈕時，鍵盤連點的放開階段仍會保留那個實體長按。

設定格式升為版本 2；載入舊版本 1 保留原本所有自訂鍵，連點預設關閉。只有按下儲存才寫入新格式。舊程式無法讀取新格式，回退前應保留舊設定檔備份。

## 錄製腳本模式

**可依目前的手把動作輸出介面開發，但尚未實作或提供成品。** 第一階段可記錄已映射的手把按下／放開與時間間隔，再提供儲存、載入、單次重播、指定次數循環及停止。記錄的是手把動作，不是所有 Windows 打字；改鍵後仍可重播相同動作。

工程上應分成明確開始／停止的錄製器、驗證過的時間序列、受前景視窗與 F8 控制的播放器。錄製與播放互斥，失焦、斷線或暫停即停止且清除輸出；不自動在重新連線後播放。檔案只容許已知動作與有限時間／步驟數，不把任意命令或程式碼當成腳本執行。

這個第一階段不會辨認遊戲畫面、找怪、判斷任務進度或自行避開載入畫面；單純重播會受讀取時間、網路延遲與遊戲狀態影響。錄製本身、手動編輯等待時間、循環次數及停止行為都需要另做測試，不能用目前連點通過來宣稱腳本完成。

## 其他實體手把：暫緩的驗證路線

目前不擴充這條路線，也不把其他實體手把相容性當作免手把首版的發布前提。下列流程保留供未來重新排入計畫時使用，現有實體 DS4 程式與成功紀錄不刪除。

Sony 官方列出 Windows Remote Play 支援 DUALSHOCK 4、DualSense 與 DualSense Edge；我們的中繼還需要逐型號實作與測試。[Sony 說明](https://remoteplay.dl.playstation.net/remoteplay/lang/en/1100001.html)

1. **準備真正的待測手把與可中斷的測試時段**。先有線直連官方 Remote Play，確認原生操作正常，保存原始驅動狀態。若日後恢復此計畫，再依需求安排型號；不在正在掛網的連線中插拔或切換。
2. **核對裝置與資料格式**。讀取待測手把的識別、USB 描述、輸入通道、報告長度與按鈕／搖桿位置，針對型號建立解析與離線範例。不能只增加一組 VID/PID 就宣稱支援；不保存帳號或驗證密鑰。
3. **先接中繼但不映射鍵盤**。保留實體控制與功能往返，確認原本手把仍能控制 PS5，且官方程式不當機。
4. **鍵盤與連點操作驗證**。逐一確認按下、長按、放開、組合方向、F8、切窗停止，並保留實體輸入。Windows 回讀到資料只是其中一步，最後必須在官方 Remote Play 連上的 PS5 畫面看到操作。
5. **恢復與穩定性**。測試拔除、重新插上、程式關閉、重開機及還原原始驅動，再做長時間操作與第二台電腦測試，才將這個型號列入支援清單。

目前實體手把中繼的本機成功案例只有有線 DS4 第一代 `054C:05C4`；第二代 `054C:09CC` 雖列在中繼允許清單，還沒有同等實測證據。免手把候選使用相同產品識別碼的虛擬裝置，其成功不等於實體第二代已通過中繼驗證。Xbox、Switch 或任意手把需要額外輸入轉換與相容輸出方案，不能直接套用目前成功結論。

## 免手把：目前主線的驗證

這條路線現為產品主線：免手把候選使用獨立模擬裝置，實體中繼另保留作歷史備援。先前候選雖能被 Windows 讀回鍵盤輸出，使用者在 PS5 畫面沒有操作效果，這份失敗紀錄仍保留。2026-10-29 的新候選取得不同結果，但兩次差異的原因尚未定位。

免手把候選的初步操作證據，必須包括**所有實體 Sony 手把已拔除、新啟動候選後，使用者在官方 Remote Play 的 PS5 畫面確認鍵盤完成明確操作**。既有 Sony 連線下操作成功與從零啟動／重新連線成功是不同驗收項目，不能互相代替。單純出現在 Windows 裝置清單、模擬相同名稱、開啟 handle 或成功送出 HID 報告，都不能單獨算操作通過。

### 2026-10-29 初步操作證據

1. 使用者先拔除 DS4；測試前未發現實體 Sony 手把，原實體手把紀錄的 bus 已不存在。
2. 獨立 [免手把實驗版](../research/controller-free-preview/README.md) 使用已核對簽章與固定版本的 VIIPER v0.9.0，以及既有 usbip-win2，只匯入自己建立的虛擬 `054C:09CC`。
3. 同一個官方 Remote Play 9.5 程序保持運作。唯讀檢查從測試前零個 DS4 handle，變成測試後一個 `09CC` handle；本次沒有重啟 Sony。
4. 使用者確認「有反應，可以用鍵盤操作」。候選同時記錄鍵盤啟用、5,127 幀輸出、2,021 幀非中立輸出且沒有失敗。操作結果以使用者的 PS5 畫面回報為據，輸出統計與 handle 只作輔助證據。
5. 唯讀 Windows HID 觀察完成 120,001 毫秒：`success=true`，56,755 份報告、171 次狀態變化、24,594 份非中立報告、0 次閒置逾時、裝置未變更。這是約兩分鐘的輸出觀察，不等於長時間掛網或每個遊戲動作均通過。

因此目前狀態是 **免手把已取得首次單機初步操作成功，並選為產品主線；尚未完成正式發布驗收**。本次沒有以重啟或中斷 Sony 連線來測試，不把既有連線成功解讀為所有啟動情境已通過。

### 接續的主要驗收關卡

同日使用者重開機後回報「開機了，功能正常」，記入 `0.1.0-alpha.5` DS4 模式的第一次重開機驗收。新 `0.1.0-alpha.6` 的 DualSense 雖已接入 Windows，使用者在 Sony 回報無反應；改回同版 PS4 模式後確認正常。主捷徑預設 PS4，DualSense 保留實驗選項；見[實機紀錄](../research/controller-free-preview/ALPHA6-TRIAL.md)，不能沿用 DS4 的驗收結果。

1. **重開機與首次啟動**：保持實體手把拔除，驗證 Windows 重開後、Sony 先開／候選先開均能正常操作；不能依賴前次留下的裝置或已建立連線。
2. **重新連線與復原**：驗證 PS5 斷線後重連、候選重開、正常退出與錯誤清理，確認不殘留按鍵、不重複匯入裝置，也不處理其他程式的裝置。
3. **完整操作與長時間使用**：驗證全部按鍵的按下／長按／放開、自訂設定、連點、切窗停止與 F8，再做長時間掛網及不同遊戲測試。兩分鐘唯讀觀察不能替代此項。
4. **其他電腦的乾淨安裝／移除**：在沒有本機研究設定的新 Windows 環境確認相依元件安裝、簽章、必要重啟、首次設定、更新及移除，並完成正式散布前的授權與發行檢查。

以上通過後才公布正式支援及評估商業發行。其他實體手把不列為本輪必要項目；錄製腳本與 Mac 仍未完成，也不從本次成功推論所有電腦或遊戲通用。
