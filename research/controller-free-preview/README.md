# 上班不要玩 — 免手把實驗版

**2026-10-29 實機測試成功：** 實體手把拔除後，使用者確認能用鍵盤操作官方 Remote Play 裡的 PS5，並於重開機後再確認功能正常。成功基準是 `0.1.0-alpha.5` 的 PS4 模擬模式。新版 alpha.6 的 PS4 模式亦確認正常；DualSense 雖已接入 Windows，首次 Sony 操作測試無反應，保留為實驗選項。詳細證據見 [LIVE-TRIAL.md](LIVE-TRIAL.md)、[alpha.6 驗收](ALPHA6-TRIAL.md)、[版本紀錄](../../CHANGELOG.md)。

沿用新版的自訂按鍵、連點與前景視窗限制；輸出改走既有 VIIPER v0.9.0 與已安裝的 usbip-win2。實體中繼版沒有手把時本來就不輸出，不能用其斷線畫面推論 Sony 是否接受模擬手把。

本程式只啟動自己核對過的本機 VIIPER 服務，建立獨立 DS4，再明確匯入自己的裝置。控制只接受 Sony 官方 Remote Play 前景按鍵；F8 暫停、切窗、編輯或斷線均清除全部連點。它不安裝驅動、不更改實體裝置綁定、不操作 PSN 帳號，也不關閉或重新啟動 Sony。

不能和實體中繼版同時使用 F8。實驗時保留 Sony，關閉其他「上班不要玩」輸入介面，並確認沒有其他 USBip 匯入。清理只依當下核對過的完整本機 URL 移除自己建立的裝置，絕不使用全裝置 detach。

## 為何再次測試

先前獨立虛擬手把已在 Windows 回讀到真實鍵盤輸入，使用者在 PS5 畫面卻沒有操作效果。當時沒有區分 Sony 是否選到這隻手把。本次在不重啟 Sony 的限制下，先確認實體 Sony 手把均不存在，再建立實驗手把，對照：

1. USBip 是否成功接入預期 `054C:09CC` 裝置。
2. Sony 是否開啟該型號的 HID handle。只讀取 handle 中繼資料，不讀取 Sony 記憶體或消耗其輸入。
3. Windows 是否收到使用者自己的按下／放開；共用唯讀觀察器只回報統計數，不保存按鍵歷史或封包。
4. 最後由使用者確認官方 Remote Play 裡的 PS5 是否操作成功。

有 handle 不等於 Sony 已採用輸入，Windows 能讀資料也不等於 PS5 接受。本次有使用者在 PS5 畫面的操作確認作為實機成功依據；先前候選失敗的根因仍未定位，不能將裝置建立順序直接說成已證實的修正原因。

## 下一次開機測試

1. 保持實體手把拔除，開啟桌面的「上班不要玩（免手把測試）」捷徑。
2. 等程式完成連接後，開啟官方 Remote Play 並連上 PS5。
3. 按 F8 啟用，保持 Remote Play 為前景視窗，在主畫面或暫停選單試十字方向。alpha.7 新預設用 Home／End 作上／下，鍵盤方向鍵則是 △／□／×／○；舊自訂設定依自己的鍵位操作。
4. 再按 F8 可暫停。切換視窗會停止連點，切回後須重新觸發。

使用者已確認 alpha.5 一次重開機後功能正常，其他開啟順序與反覆重連仍待測。原本實體手把中繼捷徑仍保留，勿同時啟動兩個版本。

## 建置與操作參數

`Build.ps1` 只建置獨立目錄並複製已核對雜湊及簽章的官方 VIIPER。它不啟動程式或裝置。使用 `--connect` 才在視窗完成鍵盤擷取後開始建立實驗裝置；預設鍵盤暫停，仍須使用者按 F8。

版本取自根目錄 `VERSION`，建置自動產生 `BUILD.json`、PE 版本及 SHA-256 清單。交付候選使用 `-RunTests -RequireClean`，禁止覆寫既有輸出；完整規則見[版本控管](../../docs/VERSIONING.md)。

可用 `--controller dualshock4`（預設）或 `--controller dualsense` 選模式，亦可在尚未建立裝置時使用畫面下拉選單。單獨選模式不會建立手把。連接期間不可切換，須先正常移除自己的裝置。兩模式使用同一互斥鎖，避免同時接管 F8 或服務通道。

alpha.7 的[預設鍵位](../../docs/DEFAULT-KEYS.md)依左右手操作區重排。升級保留既有設定；要採用新配置，開啟「按鍵與連點設定」→「恢復預設」→「儲存」，此動作也會關閉原連點設定。

PS5 模式使用 VIIPER 原有 DualSense 實作與 `054C:0CE6`，不是改名或把 DS4 的 PID 改掉。輸入格式、PS／觸控板位元及回饋長度均按 DualSense 處理。目前範圍是鍵盤動作，沒有宣稱完整體感、自適應扳機、USB 音訊或進階觸覺支援。獨立後端回讀見 [DualSense 測試](../dualsense-usb-test/README.md)。

可選 `--status-file <本機完整 JSON 路徑>`，只寫入程序／服務識別、輸出數量、匯入位置與預定義錯誤碼。`usbAttachedVerified` 只表示匯入位置已核對；`sonyAcceptanceVerified=false` 表示本程式不會自行宣稱 PS5 操作成功。

VIIPER 的輸出經過篩選，只記錄請求種類、報告 ID、長度、錯誤分類及行數；不保存任意原始文字、原始 USB 封包或帳號資料。服務的啟動收據及測試資料只保留在本機輸出目錄，不納入儲存庫。
