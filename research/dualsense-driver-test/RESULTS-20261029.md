## 驅動與清理證據

- 安裝官方 **0.9.8.1** x64 套件，驗證 `usbip.exe`／`libusbip.dll` 與本機唯讀核對的 SHA-256 一致；實際載入 `usbip2_ude.sys`、`usbip2_filter.sys`，檔案雜湊相同且 Microsoft 簽章有效。
- 四次安裝器均回 `3010`；使用 `/NORESTART`，沒有重開 VM。此安裝器設定 `AlwaysRestart=yes`，本次已證實在這些 VM 中不重啟也完成接入與讀回，不能將該退出碼單獨解讀為失敗。
- 每台 VM 初始與結束的 imported ports 均為空；測試先送 neutral，只 detach 經完整 URL 核對的自有 port，再移除自有 bus，確認自有 HID 路徑消失。
- 四個 lab 均正常 `exit 0`，沒有強制終止測試或後端，沒有清理錯誤。沒有自動更換驅動、全域 detach、Sony 程序或 PSN 連線。

## 能證明與尚未測到的事

這證明「固定候選底層網路後端＋配套 0.9.8.1 CLI／DLL／driver＋四個 persona」能完成此次 Windows HID 工作負載。測的是另寫的受限入口；原候選正式 EXE 的舊版啟動限制及 native ABI 並未因此消失。

`windows-2025` 是 Windows Server，並非使用者的 Windows 11。本輪沒有官方 Remote Play、PS5 遊戲操作、真鍵盤前景／F8、feature report、音訊串流、完整觸覺、長時間運行或重開機後測試。包含音訊介面的裝置通過 HID 測試，不代表音訊串流通過；[靜態研究中的 ISO 邊界](COMPATIBILITY.md) 仍需保留。

使用者已要求製作可逐一切換四種方案的測試版本。後續另建玩家候選、先做離線保護／傳輸檢查，再交付新版本；保留 alpha.8 及 PS4 回退，不在本機執行本資料夾的 hosted 安裝／測試流程，也不重啟 Remote Play。
